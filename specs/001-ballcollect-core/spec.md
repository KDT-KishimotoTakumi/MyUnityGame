# Feature Specification: BallCollect 基本ゲーム

**Feature Branch**: `001-ballcollect-core`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "BallCollect（ハンズオン資料「AIエージェントによるUnityゲーム開発 — unity-cliハンズオン」準拠）の基本ゲーム。B1 初期状態 / B2 移動 / B3 回収 / B4 クリア / B5 落下 / B6 Rで再開。範囲外: 敵、外部アセット、効果音、複数ステージ、ランキング、オンライン機能、動画収録、実行ファイルのビルド。追加ルール（30秒制限など）は別機能として後で扱う。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初期状態のステージが表示される（B1）(Priority: P1)

プレイヤーがゲームを開始すると、床の上に自分の球と5個のアイテムが並び、固定された視点から全体が
見渡せる。画面には回収数「0/5」が表示され、CLEAR は表示されていない。

**Why this priority**: 以降のすべての操作・確認の土台であり、これだけで「何をするゲームか」が伝わる。

**Independent Test**: ゲームを開始し、配置と表示を確認するだけで検証できる。

**Acceptance Scenarios**:

1. **Given** ゲーム未開始, **When** ゲームを開始する, **Then** 20×20 の床、球（位置 X=0, Z=−7）、
   アイテム5個（X=0、Z=−4, −1, 2, 5, 8）、方向が分かる固定視点が表示される
2. **Given** ゲーム開始直後, **When** 画面を見る, **Then** 回収数は「0/5」で、CLEAR は表示されていない

---

### User Story 2 - WASD で球を動かす（B2）(Priority: P1)

プレイヤーは W/A/S/D キーで球を前後左右に転がせる。画面上で押した方向に球が動いたと分かる。

**Why this priority**: 操作できなければゲームにならない。US1 と合わせて最小の遊べる形になる。

**Independent Test**: 各キーを短時間押し、押す前後の球の位置を比べて検証できる。

**Acceptance Scenarios**:

1. **Given** 初期状態, **When** W を約1秒押して離す, **Then** 球の Z 座標が増える
2. **Given** 初期状態, **When** S を押す, **Then** Z 座標が減る
3. **Given** 初期状態, **When** D を押す, **Then** X 座標が増える
4. **Given** 初期状態, **When** A を押す, **Then** X 座標が減る
5. **Given** 球が動いている, **When** キーを離す, **Then** 新たな加速はなくなる

---

### User Story 3 - アイテムを回収して CLEAR する（B3・B4）(Priority: P2)

球がアイテムに触れるとアイテムが消え、回収数が1増える。5個すべて集めたときだけ CLEAR が表示される。

**Why this priority**: ゲームの目的そのもの。US1・US2 ができてから意味を持つ。

**Independent Test**: 球をアイテムへ動かし、回収数・アイテムの有無・CLEAR 表示の変化を確認して検証できる。

**Acceptance Scenarios**:

1. **Given** 回収数 0/5, **When** 球が1個目のアイテムに触れる, **Then** そのアイテムが消え、表示が「1/5」になる
2. **Given** あるアイテムに触れた直後, **When** 同じ接触が続く・再度判定される, **Then** 回収数は1回分しか増えない
3. **Given** 回収数 4/5, **When** 球が最後のアイテムに触れる, **Then** 表示が「5/5」になり CLEAR が表示される
4. **Given** 回収数 1〜4/5, **When** 画面を見る, **Then** CLEAR は表示されていない

---

### User Story 4 - 落下と R キーで初期状態に戻る（B5・B6）(Priority: P2)

球が床から落ちたとき、またはプレイヤーが R キーを押したとき、ゲームは開始直後とまったく同じ状態に戻る。
位置だけでなく、速度・回収数・アイテム・表示もすべて戻る。

**Why this priority**: 失敗からのやり直しと、何度でも検証できることを保証する。

**Independent Test**: 1個回収した後に落下またはRを行い、初期状態の5項目がすべて戻ることを確認して検証できる。

**Acceptance Scenarios**:

1. **Given** 1個回収済み（1/5）, **When** 球が床の外へ落ちる, **Then** 球は初期位置で静止し、回収数 0/5、
   アイテム5個がすべて再表示、CLEAR 非表示になる
2. **Given** プレイ途中, **When** R を押す, **Then** 上と同じ初期状態になる
3. **Given** CLEAR 表示中, **When** R を押す, **Then** 上と同じ初期状態になり、再びプレイできる
4. **Given** 初期化直後, **When** 再びアイテムを回収する, **Then** 通常どおり 1/5 から数えられる

---

### Edge Cases

- 球が2個のアイテムに同時に触れた場合、それぞれ1回ずつ数え、合計2増える（同じアイテムを二重に数えない）。
- 5個目の回収と落下判定が同じ瞬間に起きた場合でも、結果は「CLEAR のまま」か「初期状態」のどちらかに
  一貫し、回収数とCLEAR表示が食い違う状態にならない。
- CLEAR 後も球は操作でき、落下すれば初期状態に戻る。
- R を押し続けても、初期状態のまま変化しない（1回押すごとに初期化され、状態が壊れない）。
- 落下中に R を押した場合も、同じ初期状態になる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ゲーム開始時、20×20 の床、球（X=0, 高さは床上, Z=−7）、アイテム5個（X=0, Z=−4, −1, 2, 5, 8）、
  固定視点を表示しなければならない（B1）。
- **FR-002**: 開始時の回収数は 0 で「0/5」と表示し、CLEAR は表示してはならない（B1）。
- **FR-003**: W で +Z、S で −Z、D で +X、A で −X の方向へ球を動かさなければならない（B2）。
- **FR-004**: 視点は固定で、画面上の上下左右が操作方向と対応して分かるものでなければならない（B2）。
- **FR-005**: 球が触れたアイテムは消え、回収数を1増やさなければならない（B3）。
- **FR-006**: 1個のアイテムは、初期化されるまでに最大1回しか数えてはならない（B3）。
- **FR-007**: 回収数の表示は常に「n/5」の形で現在値と一致しなければならない（B3）。
- **FR-008**: CLEAR は回収数が5になったときにのみ表示し、それ以外では表示してはならない（B4）。
- **FR-009**: 球が床の高さより一定以上下に落ちたら、ゲーム全体を初期化しなければならない（B5）。
- **FR-010**: 初期化では、球の位置・球の速度（回転を含む）・回収数・全アイテムの表示・UI表示（回収数とCLEAR）を
  すべて開始時と同じ状態に戻さなければならない。位置だけを戻してはならない（B5・B6）。
- **FR-011**: R キーで、プレイ途中でも CLEAR 後でも FR-010 と同じ初期化を行わなければならない（B6）。
- **FR-012**: キーボード入力（W/A/S/D/R）は1種類の入力方式に統一しなければならない（B6）。
- **FR-013**: 球の位置・回収数・各アイテムの有無・CLEAR 表示の有無は、外部の自動確認ツールから
  決まった名前で読み取れなければならない（検証用）。
- **FR-014**: 範囲外の要素（敵、外部アセット、効果音、複数ステージ、ランキング、オンライン機能、
  動画収録、実行ファイルのビルド）を追加してはならない。

### Key Entities

- **プレイヤー（球）**: 操作対象。位置と速度を持つ。名前で識別できる。
- **アイテム**: 5個。それぞれ「未回収／回収済み」の状態を持ち、回収済みは非表示。
- **ゲーム状態**: 回収数（0〜5）、クリア済みかどうか。初期化で開始時の値に戻る。
- **表示（HUD）**: 回収数「n/5」と CLEAR の表示。ゲーム状態と常に一致する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: B1〜B6 の6条件すべてが、実際の操作と状態の読み取りによって「確認済み」と記録される。
- **SC-002**: W/A/S/D それぞれを1秒押したとき、4方向すべてで期待した軸の座標が変化する（4/4方向）。
- **SC-003**: 同じアイテムへの接触で回収数が2以上増えるケースが、検証中に0件である。
- **SC-004**: 初期化（落下・途中R・クリア後R の3パターン）の後、初期状態の5項目（位置・速度・回収数・
  アイテム5個・CLEAR非表示）が3パターンすべてで一致する。
- **SC-005**: 回収・クリア判定・初期化のロジックに対する自動テストがあり、すべて成功する。
- **SC-006**: プレイ中にエラーが1件も記録されない。

## Assumptions

- 球とアイテムの色、移動速度は資料の「調整可」に従い、実装時に見やすい値を選ぶ（例：球は青、アイテムは黄色）。
- 落下の判定は、床面より十分下（例：高さ −5 未満）に到達した時点とする。
- 床の端に壁は置かない（落下ルールを成立させるため）。
- 移動は物理的に転がる動きとし、斜め入力（W+D など）は両方向の合成として扱う。
- 時間制限などの追加ルールは本機能に含めず、別機能（002 以降）として扱う。
- ハンズオンの提出物 requirements.md / implementation-plan.md / verification.md は、それぞれ本 spec.md、
  plan.md・tasks.md、検証記録として対応させる。
